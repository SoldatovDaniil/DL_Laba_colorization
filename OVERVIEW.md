# Кратко о репозитории

**Что это.** Форк [richzhang/colorization](https://github.com/richzhang/colorization), упакованный в Docker для лабораторной по DL.
Задача — автоматическая колоризация ч/б фото: на вход яркость L (пространство Lab), на выход — цветовые каналы ab. Обучения нет, только инференс предобученных весов на CPU.

**Пайплайн** (`colorizers/util.py`, `demo_release.py`):
RGB → Lab → берём L, ресайз до 256×256 → модель предсказывает ab (2×256×256) → ab апсемплится до исходного размера, склеивается с исходным L → обратно в RGB.

**Что такое Lab.** Цветовое пространство, где яркость отделена от цвета:
- **L** — яркость, 0 (чёрный) … 100 (белый). По сути это и есть ч/б картинка.
- **a** — ось зелёный (−) ↔ красный (+), **b** — ось синий (−) ↔ жёлтый (+). Примерно −110…+110, `ab = (0, 0)` — серый.

Поэтому колоризация в Lab удобна: L уже известна из ч/б фото, модели нужно предсказать только 2 канала ab, а яркость исходника сохраняется один в один.

**Размерности** (формат PyTorch `N × C × H × W`: N — число картинок в батче (здесь 1), C — каналы, H — высота, W — ширина):

| | Вход | Внутри | Выход |
|---|---|---|---|
| **ECCV16** | `1×1×256×256` — канал L | энкодер сжимает до `512×32×32`, декодер поднимает до `313×64×64` (вероятности по 313 цветам), свёртка 1×1 → `2×64×64`, апсемпл ×4 | `1×2×256×256` — каналы a, b |
| **SIGGRAPH17** | `1×1×256×256` — канал L; внутри к нему приклеиваются подсказки ab (2 канала, нули) и маска (1 канал, нули) → `1×4×256×256` | U-Net: `256 → 128 → 64 → 32` (512 каналов) и обратно до 256 со skip-соединениями | `1×2×256×256` — каналы a, b (tanh × 110) |

Вход нормируется внутри модели: `(L − 50) / 100`; выход денормируется: `ab × 110`. Сеть всегда работает на 256×256. Итоговая картинка имеет исходный размер: в `postprocess_tens` ab интерполируется до `H_orig × W_orig` и склеивается с исходным L (`1×3×H_orig×W_orig` в Lab), затем переводится в RGB `H_orig × W_orig × 3`.

## Модели

**ECCV16** — Zhang et al., *Colorful Image Colorization*, 2016 (`colorizers/eccv16.py`).
Для каждого пикселя модель предсказывает не сам цвет, а вероятности 313 цветов: пространство ab нарезано на 313 ячеек. Так колоризация становится **классификацией**, а не регрессией, и цвета получаются сочными, а не усреднёнными бурыми. Архитектура — VGG-подобная CNN (VGG — классическая сеть Visual Geometry Group, Оксфорд, 2014: стопки свёрток 3×3, каналы растут 64→128→256→512 по мере уменьшения картинки) из 8 блоков свёрток с BatchNorm, без pooling (уменьшение размера свёртками со stride 2), с dilated-свёртками в середине для большого поля зрения; в конце свёртка 1×1 превращает распределение в один цвет ab как взвешенное среднее центров ячеек.

**SIGGRAPH17** — Zhang et al., *Real-Time User-Guided Image Colorization*, 2017 (`colorizers/siggraph17.py`).
Модель напрямую предсказывает значения a и b для каждого пикселя (**регрессия**, выход через tanh). Архитектура — U-Net: энкодер сжимает картинку, декодер разворачивает обратно, а skip-соединения передают мелкие детали из энкодера, поэтому границы цвета получаются чётче. Особенность — сеть изначально интерактивная: кроме L она принимает подсказки пользователя (цветные точки ab + маска), но здесь подсказки пустые, и модель работает в **автоматическом** режиме.

Веса качаются из S3 автора при сборке Docker-образа.

## Запуск

```bash
docker build -t colorization .
docker run --rm colorization                       # тест RunCheckerTest.py
python demo_release.py -i imgs/ansel_adams3.jpg    # колоризация картинки
```

## Тест (`RunCheckerTest.py`)

Проверяет: модели загружаются; выход имеет форму `(1, 2, 256, 256)`; на 3 цветных картинках из ImageNet (на вход — только L) результат ближе к цветному оригиналу, чем серый baseline без раскраски (ab MAE лучше на ≥25%, плюс PSNR > 18, SSIM > 0.75, |ab| > 5); два прогона дают одинаковый результат.
Текущий результат: все 4 проверки проходят. ab MAE: ECCV16 13.2, SIGGRAPH17 13.5, серый baseline 21.3.

**Метрики** (считаются между результатом и цветным оригиналом, усредняются по 3 картинкам):

| Метрика | Что меряет | Лучше | Порог |
|---|---|---|---|
| **PSNR**, дБ | Попиксельная ошибка в RGB: `10·log10(1 / MSE)`. Чем меньше отличия, тем выше | больше | > 18 |
| **SSIM** | Структурное сходство (локальные яркость, контраст, структура), 0…1. Т.к. L берётся из оригинала, он высокий даже у серой картинки — проверка скорее «не сломали изображение» | больше | > 0.75 |
| **ab MAE** | Средняя абсолютная ошибка по каналам a и b — напрямую «насколько угадан цвет», яркость не влияет | меньше | на ≥25% меньше, чем у серого baseline |
| **\|ab\|** | Средняя насыщенность выхода (модуль a и b). Около 0 — модель ничего не раскрасила | больше | > 5 |

**Серый baseline** — та же картинка с `ab = 0` (т.е. просто ч/б). Это «модель», которая ничего не делает; нормальная колоризация обязана быть ближе к оригиналу, чем она.
